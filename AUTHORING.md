# Connector authoring

Create and maintain PDPP Collection Profile implementations in this repository under `connectors/<key>/`. Keep the connector's code, `manifest.json`, icon, tests, and reviewed scrubbed fixtures together. Use the shared runtime in `packages/polyfill-connectors/src/`. The [PDPP Collection Profile](docs/spec/collection-profile.md) is the normative manifest and wire contract. The [runtime note](packages/polyfill-connectors/docs/collection-profile-runtime.md) records current package entry points and known implementation gaps.

## Local authoring loop

Run these commands from the repository root after `npm ci`. `--json` writes to the path as given, relative to the current working directory; using the root keeps the claim at `connectors/<key>/evidence/claim.json`.

1. **Scaffold:** `node --import tsx packages/polyfill-connectors/bin/connector-init.ts <key> [--display-name <name>] [--stream <stream>] [--browser]`. The key and stream use lowercase snake_case. The default creates an API connector; `--browser` creates a browser connector. The command refuses to overwrite existing paths.
2. **Run and watch:** `node --import tsx packages/polyfill-connectors/bin/connector-dev.ts <key> [--streams <name,name,...>] [--summary-out <path>]`. This runs the connector against its live upstream using configured credentials and prints records and progress locally. It is a development run, not an ingest proof. Keep output and summaries private.
3. **Capture:** `node --import tsx packages/polyfill-connectors/bin/scenario-record.ts <key> [--runs 1|2] [--streams <name,name,...>] [--record-har]`. By default it records two runs. `--runs 1` records only the first. The default scenario destination is `packages/polyfill-connectors/runs/<key>/`; captures, HAR files, storage state, and run output can contain account data or credentials. Keep them local; do not blindly commit or share them. Two runs do not by themselves prove full-refresh or incremental semantics.
4. **Replay:** `node --import tsx packages/polyfill-connectors/bin/scenario-verify.ts <key> <scenario-path> [--require-capture-source]`. Replay runs the current connector against the captured interactions. A passing replay checks output against that scenario; it does not collect fresh account data or establish provider freshness or stability under provider churn. The optional source flag also requires source and declaration digests to match capture time. Use the scenario path printed by capture (normally `packages/polyfill-connectors/runs/<key>/<file>`).
5. **Write dated evidence:** after replay, write the verifier's claim record with `--json connectors/<key>/evidence/claim.json` and review the generated file before committing it. Since this command runs from the repository root, it writes to the root connector directory. The record includes capture and verification timestamps, claim, limitations, stream coverage, run/driver counts, digests, and scenario filename. Commit the claim only; keep its scenario and related raw files private. A `diagnostic_replay` claim records limitations. Currently `recorded_replay` is withheld for every driver pending independent review of the isolation evidence boundary. See the [scenario claim details](packages/polyfill-connectors/docs/connector-authoring-guide.md#92-scenario-replay-evidence-claimjson) for interpretation and boundaries.

Follow the [connector checklist](packages/polyfill-connectors/CONNECTOR-CHECKLIST.md), then run package verification and focused tests. For artifact build and publication flow, see the repository README and `scripts/build-connector-oci-artifact.mjs` / `scripts/verify-connector-oci-artifact.mjs`.

The historical Playwright scope catalog is frozen. A new Collection Profile stream does not automatically replace a Desktop scope or authorize writing raw records under a legacy scope ID. Such a replacement needs a separately reviewed projection and consumer activation.
