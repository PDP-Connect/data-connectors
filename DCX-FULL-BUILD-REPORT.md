# Full connector package build report

## Outcome

`@pdpp/polyfill-connectors` now publishes a JavaScript implementation, declaration file, and declaration map for every one of the 45 manifest-listed connector IDs. The generated `packages/polyfill-connectors/connector-index.json` records each manifest, icon, and package-relative built entry. The package exports every connector subpath and the new `@pdpp/polyfill-connectors/resolve` API.

The build now compiles `connectors/**/*.ts`, checks that the generated index is current, and retains the published-entrypoint and packed-artifact guards. The packed artifact rejects package-authored raw `.ts` files and JavaScript that imports raw TypeScript. The Slack connector's `config/slackdump-api-config.toml`, a runtime dependency discovered during review, is also explicitly included and checked in the packed tarball.

## Resolver contract for data-connect

```ts
import { fileURLToPath } from "node:url";
import { resolveConnectorImplementation } from "@pdpp/polyfill-connectors/resolve";

const implementation = resolveConnectorImplementation(connectorId);
await import(implementation.entry);
const executablePath = fileURLToPath(implementation.entry);
```

`resolveConnectorImplementation(connectorId)` returns `{ entry, manifest, brandIcon }`. `entry` is a directly importable `file:` URL for the installed package's built JavaScript entrypoint. `brandIcon` is a `file:` URL for the installed SVG. `manifest` is the indexed manifest object. An unknown ID throws `ConnectorImplementationNotFoundError` with code `ERR_PDPP_CONNECTOR_IMPLEMENTATION_NOT_FOUND`. The data-connect controller must call this resolver and, when it needs a process argument, use `fileURLToPath(entry)`; it must not enumerate manifest or connector directories.
