# Scenario consumer contract

Saved scenarios and scripted callers can stop working if a recorder or verifier changes a field, replay rule, CLI option, or claim artifact without a version change. This document freezes the intended consumer contract against baseline `a8ebdb978a03ae64c33bdd84f1e46b8c6f1e4f30`; it records existing behavior and adds documentation policy, with no runtime or validator changes in this phase.

## Scenario JSON: `pdpp.connector-scenario/1`

Consumers identify the wire version from top-level `format`. The controlling code constant is `SCENARIO_FORMAT` in [`format.ts`](../src/scenario/format.ts#L26), and `validateFormat` accepts that exact value ([`validate.ts`](../src/scenario/validate.ts#L64-L70)). Package and recorder versions do not select the scenario format.

The TypeScript interfaces in [`format.ts`](../src/scenario/format.ts#L59-L87) and [`format.ts`](../src/scenario/format.ts#L104-L163) are the normative producer inventory. Top level requires `capture`, `connector`, `format`, and `runs`; `normalizers` is optional ([`format.ts`](../src/scenario/format.ts#L807-L813)). `capture` requires `captured_at`, `complete`, `evidence_class`, `privacy_class`, and `recorder_version`; `provider_contact` is optional. `connector.id` is required; its capture-time digest fields and `tool_version` are optional. `captured_with` contains optional source and declaration digests.

Each run requires `expected`, `interactions`, and `start`; `clock`, `environment`, and `user_interactions` are optional ([`format.ts`](../src/scenario/format.ts#L784-L805)). `start` requires `scope` and `state`; `state_from_run` is optional. `expected` requires `final_state` and `records`; `protocol_trace` is optional ([`format.ts`](../src/scenario/format.ts#L677-L693)). Each stream expectation requires `count`, `ids`, `ops`, and `record_sha256s` ([`format.ts`](../src/scenario/format.ts#L363-L393)). Each HTTP interaction requires `request`, `response`, and `seq`; request requires `method`, `origin`, `path`, and `query`, while response requires `body` and `status` ([`format.ts`](../src/scenario/format.ts#L191-L226)). The recorded-browser network driver requires `driver: "recorded-browser"`, `har_entry_count`, `har_path`, and `storage_state_path`; `environment.network` itself is optional ([`format.ts`](../src/scenario/format.ts#L728-L781)). The interfaces define further nested fields and optionality; they are the source of truth for producer shape.

The runtime validator is narrower than full TypeScript shape validation: it checks the exact format, `capture.complete === true`, a non-empty connector ID, non-empty runs, state references, run structure, and stream operation alignment ([`validate.ts`](../src/scenario/validate.ts#L64-L98), [`validate.ts`](../src/scenario/validate.ts#L259-L305), [`validate.ts`](../src/scenario/validate.ts#L384-L393)). In particular, it does not require `capture.captured_at`; old accepted inputs may omit it. Consumers must not infer that every interface type or required property is enforced at runtime.

Unknown properties are **not generally ignorable**. `/1` permits additional informational optional members at the scenario root, distinct from `format`, `capture`, `connector`, `normalizers`, and `runs`; consumers ignore these root members, and their absence must not change acceptance, replay, or claim semantics. This rule applies only to informational root members. Trace entries are compared through `JSON.stringify`, so entry keys and property order affect equality ([`verify.ts`](../src/scenario/verify.ts#L1413-L1428)); stream membership is exact ([`verify.ts`](../src/scenario/verify.ts#L2034-L2059)); final state is hashed as a whole ([`verify.ts`](../src/scenario/verify.ts#L2090-L2098)). Unknown payload, state, stream-map, trace, request, response, and driver keys can therefore change replay meaning or fail replay. The environment index signature and historical comments describing additive driver fields are implementation history, not a blanket forward-compatibility promise ([`format.ts`](../src/scenario/format.ts#L695-L700), [`format.ts`](../src/scenario/format.ts#L767-L781)). Existing optional fields may remain absent with their documented legacy behavior.

Freeze `/1` acceptance and replay semantics for advertised inputs, including older captures and optional-field absence. A breaking field, meaning, encoding, enum, ordering/comparison rule, or replay change requires a new top-level format value, an update to `SCENARIO_FORMAT`, and a migration statement that names the prior version and states whether support continues or is dropped. Do not add a multi-version engine preemptively. Dropping prior support requires an explicit rejection test and a pinned prior verifier or documented migration route; consumers must not silently skip old fixtures. Historical comments saying a driver could be added without a bump describe pre-freeze development, not future policy.

## CLI contract

The stable CLI identity is `pdpp.connector-scenario-cli/1`. It is declared in [`bin/scenario-cli-contract.json`](../bin/scenario-cli-contract.json), beside the invoked `scenario-record.ts` or `scenario-verify.ts`. A consumer resolves the actual invoked bin path and reads this sibling file; it must not use the current working directory. Missing metadata means the CLI contract is unversioned. CLI contract changes that break documented flags, defaults, exit meanings, or machine artifacts require a new contract identifier. There is no runtime `--version` flag. The metadata must ship with the bins wherever those bins are distributed; the current private npm package file allowlist excludes `bin/`, so its tarball currently ships neither the bins nor this metadata ([`package.json`](../package.json#L4-L16)).

`scenario-record <connector>` defaults to two runs, all registered streams, a timestamped `runs/<connector>/<iso>-scenario.json` output path, a 300-second inactivity timeout, and no HAR ([`scenario-record.ts`](../bin/scenario-record.ts#L20-L29), [`scenario-record.ts`](../bin/scenario-record.ts#L505-L510), [`scenario-record.ts`](../bin/scenario-record.ts#L919-L930)). Stable options are `--runs 1|2`, `--out <path>`, repeatable `--answer <id-or-index>=<value>`, `--answers <json-file>`, `--persist-otp`, `--streams <name,name,...>`, `--timeout <seconds>`, and `--record-har`; `--entrypoint <path>` is a local/test override that the parser accepts even though usage text omits it ([`scenario-record.ts`](../bin/scenario-record.ts#L55-L64), [`scenario-record.ts`](../bin/scenario-record.ts#L801-L873), [`scenario-record.ts`](../bin/scenario-record.ts#L895-L907)). Timeout is a positive integer. If the same answer key appears in both sources, `--answers` wins over `--answer` ([`scenario-record.ts`](../bin/scenario-record.ts#L2756-L2759)). Unknown options and usage errors exit `2`; successful complete capture exits `0`; incomplete capture or connector failure exits `1`. Unknown connector exits `2`, while an unknown `--streams` name exits `1` ([`scenario-record.ts`](../bin/scenario-record.ts#L760-L768), [`scenario-record.ts`](../bin/scenario-record.ts#L1098-L1101), [`scenario-record.ts`](../bin/scenario-record.ts#L2735-L2747), [`scenario-record.ts`](../bin/scenario-record.ts#L2823-L2835)).

`scenario-verify <connector> <scenario-path>` defaults to a 300-second inactivity timeout. It supports `--entrypoint <path>`, `--require-capture-source` (off by default), `--json <path>`, `--timeout <seconds>`, `--dump-records <dir>`, and `--dump-all-records` (off by default); no short aliases are defined ([`scenario-verify.ts`](../bin/scenario-verify.ts#L291-L365)). Timeout is a positive integer. `--dump-records` takes precedence over `PDPP_SCENARIO_DUMP_DIR` ([`scenario-verify.ts`](../bin/scenario-verify.ts#L231-L236)). Passing replay exits `0`; fatal input or replay mismatch exits `1`; usage errors exit `2` ([`scenario-verify.ts`](../bin/scenario-verify.ts#L238-L260), [`scenario-verify.ts`](../bin/scenario-verify.ts#L2551-L2573)). Human stdout/stderr wording, ordering, timing, and internal paths are not machine APIs.

For machine results, `--json <path>` writes `pdpp.connector-claim/1` on a passing replay only. Its stable subset is: `schema`; string `connector`; optional string `captured_at`; required string `verified_at`; `claim` (`recorded_replay` or `diagnostic_replay`); string-array `limitations`, `coverage`, and `drivers`; integer `runs`; `captured_with` and `verified_subject`, each with nullable-string `source_digest` and `declaration_digest`; string `scenario_path`; and `scenario_status: "candidate oracle"` ([`scenario-verify.ts`](../bin/scenario-verify.ts#L1832-L1868)). The normal producer emits `captured_at` as a string, but if an accepted legacy scenario omits `capture.captured_at`, the claim omits its `captured_at` key; consumers must not expect `null` or a fabricated timestamp. Coverage values are feature tokens, not stream names: current values are `empty_state_run` and `state_seeded_second_run_with_changed_requests` ([`scenario-verify.ts`](../bin/scenario-verify.ts#L2681-L2686)). Consumers must preserve these meanings, ignore unknown additive coverage tokens and object keys, and treat `limitations` as display text rather than stable reason codes. Incompatible claim key, type, nullability, or meaning changes require a `pdpp.connector-claim` version bump.

`--json` is not a universal result envelope: failed replay returns before writing it, leaving any prior file untouched ([`scenario-verify.ts`](../bin/scenario-verify.ts#L2551-L2557)); a write failure logs an error but preserves replay exit `0` ([`scenario-verify.ts`](../bin/scenario-verify.ts#L1869-L1877)). A consumer must use a fresh output path for each invocation, require exit `0`, and require a newly created, parseable artifact. Missing or stale output is not a result.

## Evidence and privacy

HTTP recording captures connector-process HTTP exchanges and replay checks the connector's emitted records and state offline ([`format.ts`](../src/scenario/format.ts#L7-L22), [`format.ts`](../src/scenario/format.ts#L191-L226)). HAR replay feeds recorded browser HTTP traffic to the connector's browser context and checks data mapping; it does not reproduce page choreography, WebSocket/EventSource frames, or downloads, and it cannot earn `recorded_replay` ([`format.ts`](../src/scenario/format.ts#L695-L726)). A passing replay proves behavior against the capture, not current provider behavior.

Captures are local-only and may contain sensitive response bodies, HAR headers, cookies, and browser storage state; scrub before any commit or sharing ([`scenario-record.ts`](../bin/scenario-record.ts#L44-L46), [`scenario-record.ts`](../bin/scenario-record.ts#L98-L116)). An authorized fixture exception allows real recorder output from an independently authored local reference connector and local fixture site, with no account or personal data, documented source/commands/pins/digests, and manual plus automated scrubbing before commit. These are synthetic-spike/local-only fixtures, not proof of provider integration. Do not hand-author or substitute scenario/HAR JSON for recorder output. The authoring guide's existing prohibition on committing private captures remains in force ([`connector-authoring-guide.md`](connector-authoring-guide.md#L604-L614)).
